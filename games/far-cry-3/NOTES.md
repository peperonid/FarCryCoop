**Path: 1 — finish what exists.** The FarCryCoop project is the one to build on. The parent
project (Far Cry 1) already has a working co-op architecture (ASI + script pack + Steam
launcher) that is being adapted for FC3.

### 3. Which engine?
Dunia (CryEngine 1 derivative). Same engine family as Far Cry 2 and Far Cry 4.
Key facts from the FC2 writeup (coop-anything/games/far-cry-2):
- Lua 4.0 statically linked into the engine DLL
- No SDK; archives unpacked with Gibbed.Dunia
- Netcode: `NetworkEngine`, `CNetObject*` with Host/Controller/ThirdParty roles
- Pawn replication in `*.netobject.xml` files
- Game modes in `engine\gamemodes\gamemodesconfig.xml`
- `dinput8.dll` proxy used as hook point in the FC2 probe

For FC3 specifically (from Bantila/FarCry3Coop NOTES.md):
- `FC3.dll` / `FC3_d3d11.dll` are the main engine DLLs
- Data archives use FAT v9 (newer than FC2's v5)
- Mission scripts are plain Lua generated by "Domino" tool
- 427 files in `patch.fat` (388 Lua), 3099 in `common.fat`
- Unpacked with Gibbed.Dunia (local patch added for FC3 FAT v9 support)

### 4. How much source is there?
- **Script layer:** Lua 4.0 mission scripts in the archives (Domino-generated). 388+ Lua files.
- **Native layer:** Closed binary `FC3.dll` / `FC3_d3d11.dll`. Need REA/Ghidra for RE.
- **Tooling:** FC3Editor.exe (official map editor) ships in the install.
- **No full decompilation** of the engine DLL exists.

### 5. Does the engine have multiplayer?
FC3 **did ship with an official 6-mission co-op campaign** in multiplayer (up to 4 players).
However, the online service (Agora/Ubisoft) is shut down. The engine has netcode
(NetworkEngine, pawn replication) but it was only used for the separate MP campaign,
not the single-player story.

**The Far Cry 1 (2004) co-op proves the pattern works:** the campaign map runs as a
listen server with single-player rules, and remote players join. The FC3 plan mirrors this.

### 6. Shipping check
- ASI plugin (Ultimate ASI Loader) + script pack in separate archives — no game file replacement
- No anti-cheat in FC3
- Steam invite via Spacewar bridge (AppID 480) — no direct IP needed
- Game files are NOT shipped; the mod is a separate package

## Phase 1 findings (from Bantila/FarCryCoop, 2026-10-24..25)

### Network transport
- **Network library: Ubisoft Storm** (`storm::echo::session`, `storm::echo::player`, `storm::echo::lan`, `storm::punch`). Sessions have host migration, tickets, join requests, peer routing through the host, NAT traversal.
- **Online services: Ubisoft RendezVous** (`CGameMatchmakingProvider_RdV`, `CRendezVousInitPunchOperation`, `onlineconfigservice.ubi.com`). **Shut down.**
- **LAN exists in the engine** (`storm::echo::lan::inEvent::DiscoverSession`, `BroadcastLanDiscovery2`) but the PC game layer never uses it — only `_RdV` online providers.
- **Join path options:** (A1) ASI hooks `_RdV` providers to answer locally; (A2) local RendezVous emulator; (B) own netcode on the working "Offline coop" session.
- **Command-line direct connect (developer path):** `-host -login <name> -coop` / `-client -login <name> -ip <addr>`. Session type 3 = local coop (no online). `-offline` shows a debug menu with "COOP Story".
- **Network config:** `DefaultNetworkConfig.xml` (hash `02E1D1848EC84585`): ports 9000-9004, NAT traversal, LAN discovery tunables, network emulator profiles for lag tests. No `Override*` files exist — we can add `OverrideNetworkConfig.xml`.

### Player service (CFCXPlayerService)
- Network-replicated component with 4-slot player table. In single-player, slot 0 is the local player.
- Lua-exposed: `GetNumberOfPlayers()`, `GetPlayerInSlot()`, `CoopGetCharacterName()`, `CoopTeleportPlayer()`.
- Net messages: `PlayerService_HidePlayerMessage` / `PlayerService_ShowPlayerMessage`.
- If a puppet pawn is put into slot 1, all co-op Lua boxes see it.
- Key functions: `FUN_10681070` (count), `FUN_10680ef0` (slot→id), `FUN_10680f90` (name), `FUN_1039e1f0` (component lookup), `FUN_11305eb0` (slot-0 fallback).

### scubrah's mod (Nexus 220)
- Online co-op on the single-player map: enemy AI, vehicles, outposts, full map, max 8 players.
- No story missions, ~2 GB download (repacked world archive), alpha 2020-07-10.
- Proves the engine's co-op session works on the island.
- Nexus returns 403 without login; owner needs to download.

### Solo Offline Coop mod (Nexus 262)
- Two DLL edits: `call 0x108c4b09` → 5×NOP (the "not enough players" check).
- Database: `Local Coop` playlist `minPlayersInRound` 2→1, `matchCountdownInSecs` 0→10.
- Reference for starting a co-op session without online services.
- `scripts/patch_dll.py` in the repo reproduces this patch; verified byte-identical to mod 262.

### Archive structure (scubrah's mod vs vanilla)
- Mod `patch.fat`: 3316 entries (vanilla 427): 2864 world sectors `.fcb`, 404 Lua.
- Mod `fc3_main_vistas`: 129894 entries, 3 GB (vanilla 13261, 150 MB); ~100000 share hashes with `multicommon`, ~25000 with `fc3_main`, 14309 new.

### Tools
- **Gibbed.Dunia** with local patch for FAT v9: unpacks FC3 archives.
- **FCBConverter** (Jakub Marecek): converts `.fcb` to XML and back. Ships 4.1M file names + 483K strings for naming hashes. Needs .NET 7+; runs on portable .NET 8.
- **REA** (Ghidra 12.1.4 MCP server): `FC3.dll` 40 MB, first analysis ~10 min. `REA_GHIDRA_STARTUP_TIMEOUT_MS=3600000`.

## Phase 2 findings (2026-11-01, FC3.dll binary analysis)

**Network stack: Storm (Ubisoft)** — confirmed in FC3.dll strings:
- `storm echo` — session management (Create, ChangeSessionDescription, SessionTicket)
- `storm punch` — NAT traversal (ClientImplMainInitParams, ClientImplNetworkInitParams, detectNat, qos punch/traversal)
- `storm echo` — player events: RequestJoin, AcceptJoinRequest, RefuseJoinRequest, RequestAddPlayer, RemovePlayer, UpdatePlayer
- `AcceptSessionHostCandidacy` / `RefuseSessionHostCandidacy` — host election
- `BroadcastLanDiscovery2` — LAN discovery via UDP broadcast
- `Host disconnected starts host migration` — host migration supported
- `Listening on host port` — server listen
- `WS2_32.dll` — Winsock import confirmed
- `-dedicated` flag — dedicated server mode exists
- `dedicatedConfig`, `NumPlayers`, `SessionId`, `IsDedicated`, `MapSource`

**Co-op entities in engine:**
- `CSpawnPointCoop`, `CLocalSpawnPointCoopEntity` — co-op-specific spawn points
- `CSpawnPointMP`, `CSpawnPointBlue`, `CSpawnPointRed`, `CSpawnPointShared` — MP spawn types
- `CGRQueryIsCoopGame` — co-op game mode query
- `FCXCoop` — co-op game mode identifier

**Lobby/session infrastructure:**
- `CLobbyService`, `CNetGameCtrlEnterLobby`, `CNetGameCtrlStateUpdateLobby`
- `CSessionSendInviteOperation`, `CSessionAcceptInviteOperation`, `CSessionCancelInviteOperation`
- `CVotingService`, `CPlaylistService`
- `CFCXGRStateLobby` — co-op lobby state
- Connection states: `ResolvingAddress`, `Reaching`, `Connected`, `Dropped`, `Deleted`
- Error states: `CONNECTION_FAILED`, `CONNECTION_TIMED_OUT`, `KICKED`, `BANNED`, `SESSION_JOIN_TIMED_OUT`, `REFUSED`, `MIGRATION`

**Game modes in FC3.dll:**
- `Singleplayer.feu`, `Multiplayer` menu, `QuickLaunch.feu`
- `frontendworld`, `multicommon` — world references

**Conclusion:** The engine has a complete co-op infrastructure (Storm netcode, session management, LAN discovery, host migration, spawn points). The `-host`/`-client` flags and session type 3 (co-op story) should work. The "not enough players" check at `0x108c4b09` is the main gate to bypass for solo/offline play.

## Startup / command-line behaviour of the Uplay 1.06 build (2026-11-01)

Verified on the owner's machine: `H:/Uplay/Far Cry 3` = Uplay build **1.06**
(FC3_d3d11.dll 40869416 bytes on disk / 737184512 bytes size, PE compile time 2022-05-04,
file version 1.06.0.90512, product 1089053420; MD5 FC3_d3d11 `916c6d4b876d8be5f0ad68f50719a838`,
FC3 `5742de2aaa76935d46947bf89e2e2eb7`, farcry3_d3d11.exe `47d4c992b0e82b7d52cc48e8d1bd9119`).
No 1.05 build exists anywhere on the disks (C:/Users/USER/Downloads, Desktop, D:/, E:/, H:/).

- **The exe is a DRM stub.** `bin/farcry3_d3d11.exe` (60992 bytes) starts, then re-executes the
  **canonical install** exe resolved from the registry
  (`HKLM\SOFTWARE\WOW6432Node\Ubisoft\Far Cry 3`: `InstallDir=H:/Uplay/Far Cry 3`,
  `ExecutableName=bin/FC3Updater.exe`, SKU=WW, Version=1.05, Language=Russian), passing only
  `-language=Russian`. Every extra argument is dropped.
- Consequence for the test copy: launching `H:/FarCryCoop/TestFC3/bin/farcry3_d3d11.exe` with
  `-host fc3_main -login h1 -coop` starts a child from `H:\Uplay\Far Cry 3\bin` with
  `-language=Russian` only. The test copy cannot run its own quick-launch.
- The quick-launch strings ARE present in 1.06 (`FC3.dll` command-line table `0x1fb6f6c`-
  `0x1fb74f6`): `-host` @0x1fb73cb, `-client` @0x1fb7472, `-login` @0x1fb7370, `-coop` @0x1fb73fc,
  `-offline` @0x1f36444, `-sessionuid` @0x1fb73e4, `-dedicated` @0x1f0d9dc,
  "Missing -login or -ip" @0x1fb7458. What is **absent** in 1.06: the 1.05 debug-menu strings
  "Not enough players", "Local Coop", "Coop Story".
- Renaming `bin/upc_r1_loader.dll` does not free the stub: the game exits silently ~25 s after
  launch (no window, no WER event) — the Ubisoft Connect loader is a hard start-up dependency.
- `HKLM` writes are not available to the current user (not elevated), so the registry cannot be
  redirected to a private copy. `local/registry-fc3-backup.reg` holds the original values.
- What 1.06 keeps usable: the single-instance mutex patch (`jnz` at `0x100041bb` / `0x10004092`
  -> NOPs) lets two copies run side by side; the Uplay party-list crash patch is 1.05-only (the
  pattern does not occur in 1.06, new UPC API).
- The 1.06 multiplayer menu is dead: it shows the hard-coded loc id `0x23894` = 145556 =
  `X360_EU_NETWORK_XLSP_DOWN` dialog (line 152 of the upper-fork notes, see
  `D:/Projects/Co-op Anything/FarCry3Coop-bantila/NOTES.md`). A quick-launch must therefore
  bypass the menu, not navigate it.
- Menu automation note: the menu ignores synthetic `mouse_event` clicks; keyboard scodes sent with
  `SendInput` (`local/menu.py press down|enter`) do reach the menu.
- Local-VM caveat: `local/menu.py` and `local/registry-fc3-backup.reg` are artifacts on the owner's
  machine and are not committed in this repo — recreate them from the registry values above if needed.

**Conclusion:** quick-launch co-op is impossible on this build without either (a) a 1.05 DRM-free
executable, or (b) a patched stub loader that re-executes our own copy with the quick-launch
arguments. Both need a decision from the owner.
