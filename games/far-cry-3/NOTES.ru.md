## Ответы триажа (playbook/triage.md)

### 1. Какая именно игра?
Far Cry 3 (2012, Ubisoft, Steam). Ремейка нет. Две актуальные версии: 1.05 (последняя с MP, на ней сделан мод scubrah) и 1.06 (текущая).

### 2. Уже сделано?
**Рабочего кампанийного ко-опа нет.** Но активный ресёрч идёт:

| Проект | Статус | Что синхронизирует | Последняя активность |
|---|---|---|---|
| **Bantila/FarCry3Coop** (https://github.com/Bantila/FarCry3Coop) | Исследование (Фаза 1: распаковка данных завершена) | Ничего — ещё на этапе реверс-инжиниринга | 2026-10-24 |
| **Bantila/FarCryCoop** (родительский, Far Cry 1 2004) | **0.2 бета, работает** — 2 игрока | Игроки, оружие, ИИ, миссии, смена карт, задания | 2026-10-24 |
| **scubrah "Open World Co-op"** (Nexus мод 220) | Альфа, без сюжетных миссий | Враги частично, мир частично | Неизвестно (скорее всего заброшен) |

**Путь: 1 — доработать существующее.** Проект FarCryCoop — тот, на который опираться. Родительский проект (Far Cry 1) уже имеет рабочую архитектуру ко-опа (ASI + скриптовый пак + Steam-лаунчер), которую адаптируют под FC3.

### 3. Какой движок?
Dunia (производное CryEngine 1). Та же семья, что и в Far Cry 2 и Far Cry 4.
Ключевые факты из записи по FC2 (coop-anything/games/far-cry-2):
- Lua 4.0 статически связана в DLL движка
- Нет SDK; архивы распаковываются через Gibbed.Dunia
- Неткод: `NetworkEngine`, `CNetObject*` с ролями Host/Controller/ThirdParty
- Репликация персонажей в `*.netobject.xml`
- Режимы игры в `engine\gamemodes\gamemodesconfig.xml`
- `dinput8.dll`-прокси использован как точка хука в FC2-пробе

Специфика FC3 (из NOTES.md Bantila/FarCry3Coop):
- `FC3.dll` / `FC3_d3d11.dll` — основные DLL движка
- Архивы данных используют FAT v9 (новее v5 из FC2)
- Скрипты миссий — чистый Lua, генерируемый инструментом «Domino»
- 427 файлов в `patch.fat` (388 Lua), 3099 в `common.fat`
- Распаковка через Gibbed.Dunia (локальный патч для поддержки FAT v9)

### 4. Сколько исходников доступно?
- **Скриптовый слой:** Lua 4.0 скрипты миссий в архивах (генерация Domino). 388+ Lua-файлов.
- **Нативный слой:** Закрытые бинарники `FC3.dll` / `FC3_d3d11.dll`. Нужен REA/Ghidra.
- **Инструменты:** FC3Editor.exe (официальный редактор карт) идёт в установке.
- **Полной декомпиляции** DLL движка не существует.

### 5. Есть ли мультиплеер в движке?
В FC3 **был официальный 6-миссионный кооператив** в мультиплеере (до 4 игроков).
Однако онлайн-сервис (Agora/Ubisoft) выключен. В движке есть неткод
(NetworkEngine, репликация персонажей), но он использовался только для отдельной MP-кампании,
а не для одиночной истории.

**Кооператив для Far Cry 1 (2004) доказывает, что схема работает:** кампанийная карта работает
как listen-сервер с одиночными правилами, удалённые игроки подключаются. План FC3 повторяет это.

### 6. Проверка доставки
- ASI-плагин (Ultimate ASI Loader) + скриптовый пак в отдельных архивах — без замены файлов игры
- Античита в FC3 нет
- Steam-приглашение через мост Spacewar (AppID 480) — прямой IP не нужен
- Файлы игры НЕ распространяются; мод — отдельный пакет

## Запуск и командная строка в Uplay-сборке 1.06 (2026-11-01)

Проверено на машине владельца: `H:/Uplay/Far Cry 3` = Uplay-сборка **1.06**
(FC3_d3d11.dll 40869416 байт на диске, PE compile time 2022-05-04, версия файла 1.06.0.90512,
product 1089053420; MD5 FC3_d3d11 `916c6d4b876d8be5f0ad68f50719a838`, FC3
`5742de2aaa76935d46947bf89e2e2eb7`, farcry3_d3d11.exe `47d4c992b0e82b7d52cc48e8d1bd9119`).
Сборки 1.05 на дисках нет нигде (C:/Users/USER/Downloads, Desktop, D:/, E:/, H:/).

- **exe — DRM-загрузчик.** `bin/farcry3_d3d11.exe` (60992 байта) стартует и заново запускает exe
  **из канонической установки**, путь к которой берётся из реестра
  (`HKLM\SOFTWARE\WOW6432Node\Ubisoft\Far Cry 3`: `InstallDir=H:/Uplay/Far Cry 3`,
  `ExecutableName=bin/FC3Updater.exe`, SKU=WW, Version=1.05, Language=Russian).
  Дополнительные аргументы стираются перед запуском:
  только `-language=Russian` доходит до игры.

- Следствие для тестовой копии: запуск `H:/FarCryCoop/TestFC3/bin/farcry3_d3d11.exe` с
  `-host fc3_main -login h1 -coop` порождает дочерний процесс из `H:\Uplay\Far Cry 3\bin` только с
  `-language=Russian`. Быстрый запуск из своей копии невозможен.
- Строки быстрого запуска в 1.06 присутствуют (таблица командной строки `FC3.dll`
  `0x1fb6f6c`-`0x1fb74f6`): `-host` @0x1fb73cb, `-client` @0x1fb7472, `-login` @0x1fb7370,
  `-coop` @0x1fb73fc, `-offline` @0x1f36444, `-sessionuid` @0x1fb73e4, `-dedicated` @0x1f0d9dc,
  "Missing -login or -ip" @0x1fb7458. Чего в 1.06 `нет` — строк отладочного меню 1.05:
  "Not enough players", "Local Coop", "Coop Story".
- Переименование `bin/upc_r1_loader.dll` загрузчик не развязывает: игра тихо выходит примерно за
  25 с (без окна, без события WER) — загрузчик Ubisoft Connect является обязательной зависимостью
  старта.
- Писать в `HKLM` текущему пользователю недоступно (без повышения прав), поэтому реестр нельзя
  перенаправить на приватную копию. Оригинальные значения сохранены в `local/registry-fc3-backup.reg`.
- Что в 1.06 работает: патч мютекса единственного экземпляра (`jnz` в `0x100041bb` /
  `0x10004092` -> NOPы) позволяет запустить две копии рядом; патч падения по списку Uplay-party —
  только для 1.05 (в 1.06 образец не встречается, там новый UPC API).
- Меню мультиплеера в 1.06 мертво: показывается жёстко зашитый loc id `0x23894` = 145556 = X360_EU_NETWORK_XLSP_DOWN (строка 152
  строка 152 в NOTES.md клона верхней ветки (Bantila/FarCry3Coop)
  обходить меню, а не проходить его.
- Автоматизация меню: меню не принимает синтетические `mouse_event`-клики;
  нажатия клавиш, посланные через `SendInput`, доходят до меню
  (проверено: `local/menu.py press down|enter`).

**Вывод:** быстрый запуск ко-опа на этой сборке невозможен без (а) DRM-free exe версии 1.05 или
(б) патченного загрузчика-заглушки, который мог бы запускать нашу копию с аргументами быстрого
запуска. Нужно решение владельца.
